# B3 — génération et maillage en Web Workers (L47, SPEC-PERF-004 à 010, 014)

Objectif : sortir la génération de chunks et le maillage (greedy meshing
compris) du thread principal, avec un ordonnanceur pur (priorités, budget par
image, rejet des résultats périmés), un repli synchrone sans Worker, des
transferts sans copie et des géométries réutilisées — sans changer UN SEUL
bloc ni UN SEUL sommet produit (le résultat worker est identique au résultat
synchrone).

Lire d'abord : [README](README.md), `src/contrats-vague2.js` (messages worker :
`validerMessageWorker`, `transferablesDe`, `PASSES_MAILLAGE`,
`ATTRIBUTS_MAILLAGE`), SPECS.md § L47 (textes corrigés par ce plan).

**Prérequis** : A3 (greedy meshing) fusionné dans master — branche
`worktree-agent-a0751c8bcd44f5a69` ; `buildChunk(chunk, pass, sample, lumiere,
eauDe, simplifie, fusion)` renvoie alors aussi `uvBases`/`uvReps`, et
`render.js` passe `fusion = true`. Ne démarre pas sur un master sans A3 :
tu recoderais `toGeometry` deux fois.

## 3. API

### `MC.FileChunks` (src/file-chunks.js, pur, aucune dépendance)

```js
creer(opts)   // opts = { enVolParWorker: 2, workersGeneration: 1, workersMaillage: n,
              //          integrationsGenParImage: 2, integrationsMailleParImage: 2, horloge: () => ms }
o.epoque                                  // entier ; o.nouvelleEpoque() → vide files et vols, epoque + 1
o.voulus(centres, aGenerer, aMailler)     // listes de world.chunksVoulus ([d2, cx, cz]) : priorités de l'image
o.distribuer(genre, libres)               // genre 'genere' | 'maille' → tâches [{ genre, cx, cz, priorite }] par ordre croissant de distance, marquées en vol
o.recu(msg, versionCourante)              // msg validé par ContratsV2 → 'integrer' | 'perime' | 'ignore' ; versionCourante(cx, cz) → entier
o.aIntegrer(genre)                        // au plus integrations…ParImage résultats (budget SPEC-PERF-005)
o.echec(genre, cx, cz)                    // worker en erreur : la tâche revient en file
o.oublier(cx, cz)                         // chunk déchargé : annule vol et file
o.stats()                                 // { enFile, enVol, integres, perimes }
```

### `MC.TachesChunks` (src/taches-chunks.js, pur)

```js
executerGeneration(monde, msg)   // msg 'genere' → { message: 'chunk' (contrat), transferables }  (monde.genererBrut)
executerMaillage(msg)            // msg 'maille' → { message: 'maillage', transferables } : chunkDe fictif sur msg.voisins,
                                 //   MC.Lumiere.eclairer, MC.Mesher.buildChunk × 4 passes (fusion = msg.fusion), versTableauxTypes
versTableauxTypes(raw)           // SPEC-PERF-008 : tableaux JS → Float32Array/Uint32Array + valeurs par défaut de toGeometry
instantaneVoisins(world, cx, cz) // thread principal : 9 × { blocks.slice(), etats?.slice(), eau copiée } (index 4 = centre)
```

### Ajouts à `src/world.js`, `src/lumiere.js`, `src/render.js`

```js
world.genererBrut(cx, cz)            // generateChunk SANS overrides, états, ni enregistrement → { blocks, etats|null, eau }
world.integrerChunk(cx, cz, donnees) // crée l'entrée de `chunks` (overrides, états, enregistrerLumieres), version = 1 ; idempotent si déjà là
chunk.version                        // +1 à setBlock, setEtat, touch/marquerVoisins, integrerChunk
MC.Lumiere.depuisTableaux(niveaux, ciel, sources)   // même objet que eclairer() : { niveau(), ciel(), sources }
render.appliquerMaillage(chunk, passes, lumiere, simplifie)  // passes typées → meshes ; geometries réutilisées (SPEC-PERF-014)
render.perf().geometriesCreees       // compteur d'instrumentation
```
`world.getChunk(cx, cz, true)` (synchrone) reste **inchangé** : le serveur,
les tests et le repli s'en servent. `render.syncChunk` reste, réécrit en
« `buildChunk` local + `appliquerMaillage` » (même résultat).

### `MC.Workers` (src/workers.js, navigateur)

```js
creerPool({ script, taille, onMessage, onErreur }) // → { envoyer(msg, transferables), taille, libres(), fermer() } | null si indisponible
disponible()                                         // typeof Worker, essai de création (file://, CSP)
```

## 4. Messages worker (formes exactes : contrat)

| Type | Sens | Champs | Remarque |
|---|---|---|---|
| `init` | p→w | `epoque, graine, options:{ zonePolitique }, v` | worker de génération : `MC.createWorld(graine, options)` ; `v` = `ContratsV2.VERSION` |
| `pret` | w→p | `epoque` | |
| `genere` | p→w | `epoque, cx, cz` | |
| `chunk` | w→p | `epoque, cx, cz, blocks (Uint16Array 32768), etats (Uint8Array\|null), eau{nature,flux,prof}, ms` | TRANSFÉRÉ ; `etats` null = tout à 0 (`ETATS_VIDE`) |
| `maille` | p→w | `epoque, cx, cz, version, simplifie, fusion, voisins[9]` | voisins copiés puis TRANSFÉRÉS ; `voisins[4]` obligatoire |
| `maillage` | w→p | `epoque, cx, cz, version, passes{opaque,lumineux,cutout,blend}, lumiere{niveaux,ciel,sources}\|null, ms` | TRANSFÉRÉ ; passe absente = aucun maillage |
| `erreur` | w→p | `epoque, cx?, cz?, message` | → `o.echec` puis repli si récurrent |

Ordre et idempotence : aucun ordre garanti entre workers. Un résultat
s'applique si et seulement si `epoque === o.epoque` et `version ===
chunk.version` au moment de l'intégration ; sinon il est jeté et, si le chunk
est encore voulu et `dirty`, redemandé. Un `chunk` reçu pour un chunk déjà
présent (généré entre-temps par le repli) est ignoré. Les tableaux reçus
appartiennent au thread principal (transférés) : aucun partage.

## 5. Comportement avec et sans Worker, en ligne et hors ligne

- Le même `MC.TachesChunks` tourne dans le worker ET sur le thread principal
  (repli) : résultat identique, seul l'endroit change.
- Repli : `MC.Workers.disponible()` faux, création qui lève, ou 3 `error`
  d'affilée → pool coupé, tâches en vol remises en file, exécution synchrone
  sous le budget de `MC.FileChunks`.
- En ligne : la génération reste locale (le client génère le terrain à partir
  de la graine du serveur) ; `onBloc` (game.js l. 84-92) appelle
  `world.getChunk(cx, cz, true)` pour appliquer un bloc sur un chunk absent —
  garder ce chemin SYNCHRONE (rare, et un bloc serveur ne doit jamais attendre
  un worker) ; le chunk arrivé ensuite du worker est ignoré (déjà présent).
- `remplacerMonde` (nouvelle graine) → `o.nouvelleEpoque()` + `init` à chaque
  worker de génération.
- Serveur : non concerné (aucun Worker côté Node ; `getChunk` synchrone).

## 10. Pièges connus

- `buildChunk` renvoie des tableaux JS : la conversion est coûteuse, la faire
  DANS le worker, jamais sur le thread principal.
- Les modules purs sont chargés dans le worker par `importScripts` : liste à
  tenir dans l'ordre de `index.html` (sous-ensemble). Maillage : `core`,
  `formes`, `eau`, `lumiere`, `mesher`, `contrats-vague2`, `taches-chunks`.
  Génération : dépendances de `world.js` (`Biomes`, `Carte`, `Circuits`,
  `Core`, `DayCycle`, `Densite`, `Donjons`, `Eau`, `Factions`, `Feu`,
  `Formes`, `Habitats`, `Inventory`, `Lointain`, `Lumiere`, `Meteo`,
  `Recifs`, `Routes`, `Souterrain`, `Zones`, et `noise`, `volcanisme`), puis
  `world`, `contrats-vague2`, `taches-chunks`. Anti-cache : même jeton
  `?v=` que `index.html` (`MC_VERSION`), transmis dans l'URL du worker.
- `instanceof Uint16Array` est faux d'un « realm » à l'autre : le contrat
  compare `Object.prototype.toString` ; faire de même.
- Un tampon transféré est inutilisable par l'émetteur : copier
  (`slice()`) les blocs des voisins AVANT de les transférer, jamais les
  tableaux vivants de `world.chunks`.
- `ETATS_VIDE` est un tampon partagé (copy-on-write, world.js l. 19, 465) :
  ne jamais le transférer (`etats: null` à la place).
- `chunk.lumiere` sert aussi à l'éclat des objets et créatures qui s'y
  tiennent (`MC.Lumiere.lumiereEn`, lumiere.js l. 203-208, lit
  `c.lumiere.ciel/niveau`) : `depuisTableaux` doit rendre le même objet
  qu'`eclairer`.
- Chaque worker de génération a ses propres caches de bruit (≤ 600 000
  coins) : un seul worker de génération par défaut.
- `habitats`/`routes` d'un monde de worker sont reconstruits
  déterministiquement de la graine : même terrain. Mais `zonePolitique`
  (option du serveur, `BIENVENUE.zone`) doit être transmise dans `init`.
- La CSP prévue par SPEC-SECU-010 (vague 4) devra autoriser `worker-src
  'self'` : le signaler dans le rapport.
- Contexte GPU perdu/restauré (A4) : `onContextRestored` remet les chunks en
  `dirty` ; avec la réutilisation des géométries, une restauration doit
  recréer (pas réécrire) les tampons GPU — tester le chemin A4 existant.
