# B4 — PvP : enjeux et sanctions (L46, SPEC-PVP-001 à 006)

Objectif : donner des conséquences au PvP — butin prélevé sur le vaincu,
réputation politique dégradée par les meurtres répétés, statut hors-la-loi et
embargo, succès, et un duel consenti possible partout — sans jamais toucher
aux zones sûres ni aux membres d'une même faction, par coup comme par
projectile.

Lire d'abord : [README](README.md), `src/contrats-vague2.js` (`MSG.PVP`,
`validerPvp`, `EVTS_PVP`, `messageInvMaj`), SPECS.md § L46 (PVP corrigées par
ce plan), [B1](B1.md) § 5 (helpers serveur), [B2](B2.md) § 8 (embargo).

## 4. API — `src/pvp-enjeux.js` (`MC.PvpEnjeux`)

```js
FRACTION_MIN 0.10, FRACTION_MAX 0.25, FENETRE_MEURTRES 600 (s de jeu), SEUIL_MEURTRES 3,
PENALITE 10, SEUIL_HORS_LA_LOI -50, DUREE_DUEL 120, DELAI_PROPOSITION 30, RAYON_DUEL 32, SUCCES [1, 5, 25]

creerEtat()   // { v:1, meurtres: Map nom → [heures], victoires: Map nom → n,
              //   reputations: Map nom → { factionId: valeur }, propositions: Map invite → { de, heure },
              //   duels: Map cle(a,b) → { a, b, debut, fin, centre:{x,z} } }
butinAutorise(ctx)                   // ctx { pvpAutorise, duel } → vrai seulement si PvP autorisé ET pas de duel
resoudreButin(invPerdant, invGagnant, graine) // → { perte:[{id,n}], reste:[piles non casées chez le gagnant] }
                                     //   f = FRACTION_MIN + h × (FRACTION_MAX − FRACTION_MIN), h déterministe (graine) ;
                                     //   cible = round(total × f), ≥ 1 si total > 0 ; équipement non touché ; atomique
factionsProches(politique, x, z)     // ids des factions dont |pos − siege| ≤ territoire
enregistrerMeurtre(etat, tueur, victime, heure, factions) // → { penalites:[{ id, delta, valeur }], horsLaLoi:[ids] }
reputation(etat, nom, factionId) / estHorsLaLoi(etat, nom, factionId)
embargo(etat, nom, politique, x, z)  // SPEC-PVP-006 : hors-la-loi envers une faction dont le territoire couvre (x, z)
proposerDuel(etat, de, invite, heure) / repondreDuel(etat, invite, accepte, heure, posA, posB)
duelActif(etat, a, b, heure, posA, posB)   // vrai si duel en cours ET les deux dans le rayon
expirer(etat, heure)                 // → évènements duel_fin
enregistrerVictoire(etat, nom)       // → n (compte après)
serialiser(etat) / charger(data)
```
Les noms sont des noms de connexion canonisés (`MC.Admin.canon`) ; déterminisme
par hachage (graine + noms + heure), jamais `Math.random`.

## 6. Serveur

- `case ATTAQUE` (branche `joueurCible`) : `duel = MC.PvpEnjeux.duelActif(pvp,
  a, b, heure, posA, posB)` ; autorisé si `duel` OU (`pvpAutorise` ET
  `peutBlesser`) ; à la mort (`!avant && vst.dead`) : si pas de duel →
  `resoudreButin` sur `etatJoueurServeur` des deux, reliquat
  `lacherAuxPieds(vainqueur)`, `enregistrerMeurtre` (factions proches du lieu),
  `PVP defaite/reputation/hors_la_loi` ; dans tous les cas
  `enregistrerVictoire` + `PVP victoire` ; `envoyerInvMaj` aux deux.
- Projectiles : `entities.js` fait porter `par: e.tireur` dans
  `events.degatsPar` et accepte un `opts.peutBlesser(tireurState, cibleState)`
  en plus de `pvpOk` ; le serveur le fournit (retrouve les deux joueurs par
  leur `state`, applique `duelActif`/`peutBlesser`) ; `ev.degatsPar` :
  un coup de joueur n'est plus multiplié par `regles.degatsMob`, et une mort
  suit le même chemin qu'en mêlée (fonction commune `issuePvp(vainqueur,
  vaincu)` dans la section PvP).
- `/duel` : interception dans `case CHAT` avant le test `/faction` ;
  `MC.Commandes` connaît la commande (`duel`, sous-actions).
- Tic : `expirer(pvp, heure)` dans le bloc `accChunks >= 1`, **sur la ligne
  suivant** celle de B2 (`avancerEconomie();`) — ou juste après
  `avancerPolitique();` si B2 n'est pas encore fusionné (conflit trivial).
- Persistance : `pvp: MC.PvpEnjeux.serialiser(pvp),` en dernier dans
  `etatMonde` ; `appliquerEtatMonde` : `if (data.pvp) appliquerEtatPvp(data.pvp);`.
  Duels et propositions ne sont pas persistés (éphémères).
- `MODULES` : `'pvp-enjeux'` après `'economie', 'metiers'` (ou après
  `'guildes'`).

## 13. Pièges connus

- `ev.degatsPar` n'avait pas d'auteur : un changement de forme d'évènement
  dans `entities.js` touche aussi le solo (`game.js` lit `ev.damage`,
  `ev.picked`) — garder les champs existants, AJOUTER `par`.
- Les coups de mob sont multipliés par `regles.degatsMob` (server.js l. 1363) :
  ne pas l'appliquer aux coups de joueur (aujourd'hui c'est le cas pour les
  flèches — bogue à corriger au passage, test à l'appui).
- `peutBlesser(guildes, a, b)` prend des NOMS ; `pvpOk` des POSITIONS : le
  serveur doit retrouver le joueur (nom) depuis son `state` (index
  `state → { c, j }` construit à chaque tic, comme `joueurs.find`).
- Écran partagé : deux joueurs locaux d'un même poste partagent le nom de
  connexion ; un « meurtre » entre eux est-il un meurtre ? Non : `a === b`
  → `peutBlesser` faux, rien à compter.
- Le butin doit passer par l'inventaire SERVEUR (B1) : sans rebase sur B1,
  l'intégration verrait des inventaires vides — ne pas « réparer » en
  lisant l'inventaire du client.
- `/duel` ne doit pas être diffusé dans le chat général.
