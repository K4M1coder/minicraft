# B2 — économie et métiers (L45, SPEC-ECO-001 à 007, SPEC-METIER-001 à 005, SPEC-SYNC-023)

Objectif : des prix qui bougent avec l'offre et la demande, différents selon
la région, une masse monétaire bornée (trésors des lieux, puits de monnaie),
des métiers qui produisent, consomment, progressent et se dépannent par
caravane — le tout en modules purs, joués à l'identique en solo et arbitrés
par le serveur en ligne via le seul message `TROC`.

Lire d'abord : [README](README.md), `src/contrats-vague2.js` (`TROC`,
`offreId`, `validerTrocReponse`, `validerTransaction`, `messageInvMaj`,
`MOTIFS`), SPECS.md § L45 et SPEC-SYNC-023 (textes corrigés par ce plan),
[B1](B1.md) § 5 (helpers serveur que tu appelles).

## 4. API — `src/economie.js` (`MC.Economie`)

État sérialisable, un par monde (solo : `g.economie` ; serveur : variable
`economie` dans la section B2) :

```js
{ v: 1, graine, jour,                                   // dernier jour de jeu simulé (floor(heure / DayCycle.DAY_LENGTH))
  lieux: Map lieuId → {
    id, biome, x, z,
    tresor,                                             // émeraudes du lieu (ECO-003)
    stocks: { [objetId]: { stock, ref } },              // ECO-001, METIER-001
    minerai: { [objetId]: n },                          // stock partagé du village (METIER-002)
    pnjs: { [pnjId]: { echanges } } },                  // progression (METIER-003)
  joueurs: Map canon(nom) → { collecte: { [metier]: ventes }, statuts: [metier] },   // METIER-004
  departs: Map trajetId → dernier indice de départ traité }                         // ECO-004 idempotent
```

```js
creerEtat(graine)
lieuDe(etat, lieu, contexte)            // création paresseuse, déterministe (graine + lieu.id) ; contexte = { biome, climat:{t,h}, altitude }
ressourceDe(offre)                      // objet échangé (le côté non-émeraude)
prixBaseRegional(objetId, contexte)     // ECO-002 : émeraudes par unité, facteurs par catégorie × biome bornés [0,5 ; 1,8]
prixCourant(etat, lieuId, offre)        // ECO-001 : émeraudes par lot, réel
lotExecute(offre, prix)                 // → { give:[{id,n}], get:{id,n} } (règle d'arrondi SPEC-ECO-001)
offresDe(etat, lieuId, role, pnjId, nom) // → lignes du contrat { i, give, get, prix, stock, dispo } (bonus METIER-003, remise METIER-004)
executerTroc(etat, inv, ctx)            // SPEC-SYNC-023, atomique : ctx = { lieuId, role, pnjId, indice, fois, nom, embargo? }
                                        //   → { ok:true, transaction } (ContratsV2.validerTransaction) | { ok:false, motif ∈ ContratsV2.MOTIFS }
acheter(etat, lieuId, objetId, n) / vendre(etat, lieuId, objetId, n)   // mutations de stock élémentaires
appliquerFraisBanque(slots, jours)      // ECO-005 : slots = inv.slots (piles|null) ; → émeraudes retirées
coursRegional(etat, x, z, rayon)        // ECO-006 → [{ id, prix }] (moyenne des prix courants des lieux du rayon)
tickJour(etat, jour, saison)            // régénération des stocks vers ref (pousse saisonnière METIER-001), revenu du trésor borné
passageCaravane(etat, trajet, indexDepart, contexteLieux)   // ECO-004 / METIER-005, idempotent via `departs`
simuler(opts)                           // ECO-003 : { graine, jours:100, joueurs, lieux } → { masses:[…], initiale }
serialiser(etat) / charger(data)
```

Formule recommandée (libre tant que la spec tient) : écart
`e = (ref − stock) / ref`, `prix = base × (1 + 0,6 × clamp(e / 0,75, −1, 1))` —
le plafond est atteint quand le stock tombe sous 25 % de sa référence, AVANT
l'épuisement (METIER-001 refuse à stock nul). Pousse : été ×1,
printemps/automne ×0,5, hiver 0 — même règle que `multCroissance`
(world.js l. 966-971, non exportée : la dupliquer en la citant).

`src/metiers.js` (`MC.Metiers`) : règles sans état, lues par `economie.js` —
`SEUIL_BONUS 15`, `PLAFOND 40`, `SEUIL_STATUT 20`, `REMISE 0.1`,
`OFFRES_BONUS { role: [o(give,get)…] }`, `offresActives(role, echanges)`
(METIER-003), `mineraiRequis(offre)` (METIER-002 : ex. épée de fer → 2
lingots), `metierDeCollecte(offre)` (METIER-004 : vente de blé → `fermier`),
`remise(etatJoueur, role)`.

`src/caravanes.js` : `cargaisonDe(trajet, indexDepart, stocksOrigine)` pure
(ECO-004), sans toucher à `enRoute`/`trajetsDe` (positions inchangées).

## 5. Monnaie : source, puits, trésor

- Le PNJ **paie** un achat au joueur sur `lieu.tresor` (refus `tresor` à vide)
  et **encaisse** ses ventes dans `lieu.tresor`.
- Puits : frais de garde (ECO-005) et réparation (`habitats.servir('reparer')`
  retire déjà 1 à 3 émeraudes de l'inventaire — c'est un puits tel quel) ;
  les émeraudes du frais de garde disparaissent.
- Source : revenu quotidien borné du trésor (`tickJour`), butin de donjon et
  minage (hors module).

## 6. Messages

Un seul type : `TROC` (`troc`), formes figées par le contrat.

| Sens | Forme | Traitement |
|---|---|---|
| c→s | `{ t:'troc', j, action:'consulter', eid }` | PNJ `eid` vivant à ≤ 6 blocs (`BORNES.PORTEE_TROC`) → réponse `offres` |
| c→s | `{ t:'troc', j, seq, action:'echanger', eid, offre, fois }` | `seqNouveau` ; embargo (B4, § 8) ; `executerTroc` sur `etatJoueurServeur(js).inv` ; succès → `envoyerInvMaj(c, j)` puis `offres` à jour ; échec → `refuserOp(c, j, seq, motif)` |
| s→c | `{ t:'troc', action:'offres', eid, offres:[{ i, give, get, prix, stock, dispo }], cours?, remise? }` | le client (re)dessine l'écran de troc |

Idempotence : `seq` (B1). Aucun état intermédiaire : `executerTroc` vérifie
offre, stock, trésor, possession et place (simulation d'`add` comme
`Inv.doTrade`), puis mute inventaire, stock et trésor d'un bloc.

Hors ligne : `game.js` appelle `executerTroc` sur `player.state.inv` et
`g.economie` — même fonction, même résultat. En ligne : l'écran s'ouvre sur
les offres de base, envoie `consulter`, se redessine à la réponse ; un clic
envoie `echanger` et applique une prédiction simple (aucune : attendre
l'`INV_MAJ` est acceptable pour un échange, < 100 ms en local).

## 13. Pièges connus

- `Inv.TRADES` (villageois sans métier, `ent.role` absent) : `offreId(null,
  null, i)` → `campagne|villageois|i`, pas de stock ni de trésor (illimité,
  comme aujourd'hui) — ou un trésor commun « campagne » : à trancher, mais
  jamais de refus `tresor` sur un villageois isolé sans le documenter.
- `MC.Factions.commerceOuvert(world.reputation)` (game.js l. 762) ferme déjà
  le commerce d'un village hostile : garder ce contrôle AVANT `executerTroc`,
  en solo comme au serveur.
- Les prix sont réels : n'afficher qu'un arrondi, ne jamais comparer des
  flottants par égalité dans les tests (utiliser `A.close`).
- Déterminisme : aucun `Math.random` dans `economie.js` — hachage de
  (graine, lieu, jour, …) comme `politique.js` `h01`.
- Le serveur ne connaît que les lieux proches des joueurs
  (`lieuxProches`) : un lieu jamais visité n'existe pas dans l'état ; la
  caravane vers un lieu inconnu est traitée au premier chargement de celui-ci
  (idempotence par `departs`).
- Ne pas diffuser les offres à tous : réponse au seul demandeur.
