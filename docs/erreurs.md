# Codes d'erreur — catalogue

Chaque erreur que le jeu ou le serveur journalise avec un code stable
(`E-<DOMAINE>-<NNN>`, SPEC-BANC-108) est recensée ici : sa cause et la
conduite à tenir. Le code figure dans l'entrée du journal (`MC.Journal`,
`src/journal.js`), dans le fichier du serveur (`logs/serveur-<date>.log`), dans
le rapport de test et à la console du navigateur : un `grep E-SAVE-002`
retrouve chaque occurrence.

Règles :

- un code ne change jamais de sens et n'est jamais réutilisé ; une erreur qui
  disparaît garde sa ligne, marquée « retiré » ;
- tout code écrit dans `src/` ou `server.js` doit avoir sa ligne ici
  (vérifié par `tests/spec-journal-statique.js`) ;
- le texte lisible montré au joueur (`{ joueur: … }`) ne contient pas le code :
  il est pour le joueur, le code pour celui qui lit le journal.

| Code | Domaine | Cause | Conduite à tenir |
|---|---|---|---|
| E-SAVE-001 | SAVE | Une clé du stockage des parties (index ou partie, `localStorage` du navigateur ou fichier du dossier des parties côté serveur) contient un texte qui n'est pas du JSON valide. La lecture rend la valeur par défaut (index vide, partie vierge). | Regarder la clé citée dans les données de l'entrée ; restaurer le fichier depuis une copie ou supprimer la clé corrompue. Rien n'est écrasé tant que la partie n'est pas sauvegardée. |
| E-SAVE-002 | SAVE | La sauvegarde d'une partie porte une version d'enveloppe (`slotV`) que ce jeu ne connaît pas (partie écrite par une autre version). Le joueur voit « Sauvegarde illisible ». | Ouvrir la partie avec la version du jeu qui l'a écrite, ou l'exporter puis la réimporter par le serveur ; la version trouvée et la version attendue sont dans les données de l'entrée. |
| E-SAVE-003 | SAVE | Le contenu de la sauvegarde (`MC.Save.apply`) est d'un format inconnu ou incompatible malgré une enveloppe valide. Le joueur voit « Sauvegarde illisible ». | Vérifier la version de contenu (`v`) dans les données de l'entrée ; une migration manque dans `src/save.js` si la version est plus ancienne que l'actuelle. |
| E-SAVE-004 | SAVE | Le serveur local a refusé la demande de sauvegarde immédiate du joueur (« Sauvegarder » du menu) ; le motif renvoyé par le serveur est dans les données. | Lire le motif : sans partie active, créer ou charger une partie ; demande trop rapprochée, réessayer après quelques secondes ; sinon consulter le journal du serveur à la même heure. |
| E-SAVE-005 | SAVE | La demande de sauvegarde immédiate n'a pas pu joindre le serveur local (connexion coupée, serveur arrêté). | Vérifier que `node server.js` tourne toujours ; relancer le serveur — il sauvegarde lui-même à l'arrêt, à la pause et à la cadence prévue. |
| E-SAVE-006 | SAVE | Au démarrage, le serveur a refusé le fichier de monde (JSON illisible, version inconnue ou future, reprise qui échoue). Il l'a mis de côté tel quel, octet pour octet, sous `<fichier>.refuse-<AAAAMMJJ-HHMMSS>`, et démarre une carte neuve sauvegardée sous le nom d'origine (SPEC-SAVE-026). | Le nom du fichier mis de côté et le motif sont dans les données. Pour le reprendre : arrêter le serveur et le renommer sous son nom d'origine avec une version du jeu qui sait le lire (ou le réparer). |
| E-SAVE-007 | SAVE | Le fichier de monde refusé n'a pas pu être mis de côté (renommage impossible : fichier verrouillé, droits), ou l'état vierge n'a pas pu être rétabli : le serveur n'écrit plus RIEN pendant cette session pour ne pas l'écraser ; « Sauvegarder » répond `ecriture_interdite`. | Fermer le programme qui verrouille le fichier (ou corriger les droits), arrêter le serveur, mettre le fichier de côté à la main, puis relancer. La partie jouée pendant cette session n'est pas sauvegardée. |
| E-SERV-001 | LANCEUR | Le serveur n'a pas pu ouvrir son port d'écoute (port déjà utilisé, aucun port libre dans la plage de repli, droits insuffisants). Le processus s'arrête avec le code 1. | Libérer le port, ou relancer avec `--port <n>` (ou `--port 0` pour un port éphémère) ; le motif exact est dans les données et la pile de l'entrée. |
| E-SERV-002 | LANCEUR | `--partie <id>` désigne une partie absente de l'index du dossier des parties (ou un identifiant invalide). Le processus s'arrête avec le code 1. | Lister les parties du dossier (`--dossier-parties`) et relancer avec un identifiant existant, ou sans `--partie`. |
| E-SERV-003 | LANCEUR | Les paramètres de lancement sont invalides (paramètre inconnu, valeur hors bornes ou mal formée). L'aide du paramètre fautif est affichée et le processus s'arrête avec le code 1. | Corriger la ligne de commande d'après l'aide affichée ; `node server.js --aide` liste tous les paramètres. |
| E-SERV-004 | SERVEUR | La sortie fichier du journal ne peut plus écrire (dossier `MC_JOURNAL_DOSSIER` ou `logs/` impossible à créer, droits, disque plein). Un seul avertissement à la console ; le serveur continue, son journal ne va plus qu'à la console. | Vérifier le dossier cité (droits, place libre) ou pointer `MC_JOURNAL_DOSSIER` vers un dossier inscriptible, puis relancer le serveur. |
| E-SERV-005 | SERVEUR | Le fichier du journal du jour a atteint son plafond (50 Mo par défaut, `MC_JOURNAL_MAX_OCTETS`) : une seule ligne le signale, puis plus rien n'y est écrit jusqu'au lendemain (la console continue). Souvent un flot d'erreurs répétées ou un client qui en remonte en boucle. | Lire les dernières lignes avant la coupure pour trouver la source du flot ; relever le plafond seulement si le volume est légitime. |
| E-SERV-006 | LANCEUR | Le fichier de monde (`--monde`, ou celui de `--partie`) existe mais ne peut pas être lu : c'est un dossier, il est verrouillé, ou les droits manquent. Rien n'est renommé ni écrit ; le processus s'arrête avec le code 1. | Vérifier le chemin cité (un fichier, pas un dossier), ses droits et le programme qui le verrouille, puis relancer. |
| E-SERV-007 | SERVEUR | Une exception non rattrapée (`uncaughtException`) ou une promesse rejetée sans gestionnaire (`unhandledRejection`) a atteint le gardien du processus (SPEC-SECU-002) : le serveur continue. La première occurrence est écrite avec sa pile ; la même panne répétée n'est plus écrite qu'en une ligne de compte (« s'est répétée N fois en X s ») au plus toutes les 30 s ; des pannes qui varient (identifiant, coordonnée dans le message) ne remplissent pas le journal : au plus 20 lignes par fenêtre de 30 s, le reste tient en une ligne « N pannes différentes non écrites en X s », avec la dernière ; une exception déclenche une sauvegarde de secours, la première tout de suite, puis au plus une toutes les 30 s. | Lire la pile de la première occurrence : c'est un défaut du serveur à corriger. Une ligne de compte qui revient sans cesse signale une panne en boucle : chercher sa cause avant qu'elle ne devienne une tempête (E-SERV-008). |
| E-SERV-008 | SERVEUR | Tempête de pannes : au moins 200 exceptions ou rejets en moins de 5 s. Le processus ne faisait plus que traiter des pannes ; le gardien a fait une dernière sauvegarde de secours, écrit cette ligne (`fatal`, avec la dernière panne) et arrêté le serveur avec le code de sortie 70 — plutôt que de le laisser tourner dans le vide des jours durant. | Lire les lignes E-SERV-007 qui précèdent pour trouver la panne qui boucle ; la partie a été sauvegardée juste avant l'arrêt. Corriger la cause, puis relancer le serveur. |
| E-SERV-009 | SERVEUR | La sauvegarde de secours déclenchée par le gardien des pannes (E-SERV-007, ou la dernière avant l'arrêt E-SERV-008) a elle-même échoué ; le message de l'échec suit (disque plein, droits, fichier verrouillé). Le serveur continue (ou s'arrête, s'il s'agissait de la dernière). | Vérifier l'espace disque et les droits sur le dossier des parties ; la partie peut ne pas contenir les dernières minutes de jeu. Corriger la panne d'origine (E-SERV-007 qui précède). |
| E-JOURNAL-001 | JOURNAL | La sortie console du journal est morte : l'écriture a échoué avec `EBADF`, `EPIPE`, `EIO` ou `ERR_STREAM_DESTROYED` (sortie standard fermée ou invalide : serveur relancé par une bascule de partie dont la console a disparu, exécutable lancé sans console, terminal fermé, lecteur du tube parti). La console est coupée pour le reste du processus ; cette ligne est la seule trace, dans les autres sorties (fichier du serveur, tampon). | Rien à faire pour le jeu : le journal continue dans le fichier `logs/serveur-<date>.log`, à lire là. Pour retrouver la console, relancer le serveur depuis un terminal ouvert. |
| E-RENDU-001 | RENDU | Le navigateur a perdu le contexte WebGL (pilote graphique réinitialisé, GPU retiré, trop d'onglets, mise en veille) : le rendu est suspendu, l'écran se fige sur la dernière image (SPEC-RENDU-001). | Attendre la restauration (E-RENDU-002) : le jeu reconstruit alors textures et matériaux tout seul. Si elle n'arrive jamais, recharger la page ; à répétition, mettre à jour le pilote graphique ou baisser la qualité. |
| E-RENDU-002 | RENDU | Le contexte WebGL perdu (E-RENDU-001) a été restauré : textures, matériaux et cibles de rendu sont reconstruits, les maillages de chunks sont remis en file (SPEC-RENDU-002). | Rien à faire ; le numéro de génération du contexte, dans les données de l'entrée, dit combien de fois il a été restauré depuis le chargement. |
| E-RENDU-003 | RENDU | `gl.getError()` a rendu une erreur WebGL (`INVALID_OPERATION`, `OUT_OF_MEMORY`…). Interrogé une image sur 60 et seulement en mode test (SPEC-BANC-098) : jamais dans une vraie partie. | Le nom de l'erreur et son code sont dans l'entrée ; chercher le dernier changement de matériau, de cible de rendu ou de texture, et lire l'enregistreur de vol du test juste avant. |
| E-WORK-001 | WORKER | Un worker de génération ou de maillage a levé une exception non rattrapée, ou son script est introuvable ou bloqué (politique de sécurité). Le pool bascule alors sur la génération et le maillage synchrones (SPEC-PERF-006). | Le message, le fichier et la ligne sont dans les données ; la pile complète est dans l'entrée E-WORK-002 qui l'accompagne quand le worker a pu la relayer. |
| E-WORK-002 | WORKER | Un worker a signalé lui-même une erreur : exception ou promesse rejetée vue de l'intérieur, avec sa pile (`src/worker-erreurs.js`, SPEC-BANC-097). | Lire la pile de l'entrée ; `origine` dit s'il s'agit d'une exception (`error`) ou d'une promesse rejetée (`unhandledrejection`). |
| E-WORK-003 | WORKER | Un worker a répondu « erreur » pour une tâche précise (chunk de coordonnées `cx`, `cz`) : le worker fonctionne, la tâche a échoué. La tâche revient en jeu ; trois échecs d'affilée coupent le pool. | Le message du worker est dans l'entrée ; reproduire la génération ou le maillage de ce chunk sous Node (`MC.TachesChunks`) avec la graine du monde. |
| E-WORK-004 | WORKER | Un message reçu d'un worker n'a pas pu être désérialisé (`messageerror`). | Chercher un objet non clonable dans les messages du worker (fonction, objet DOM) ; le worker concerné est dans les données. |
| E-NET-001 | NET | Le WebSocket du client a signalé une erreur (`onerror`) : serveur injoignable, refus de la poignée de main, coupure réseau. Le jeu passe en « erreur » et reste jouable en solo local (SPEC-BANC-099). | Vérifier que le serveur tourne et que l'adresse est la bonne (`url` dans les données) ; le code de fermeture qui suit (E-NET-002 ou entrée « connexion fermée ») dit comment la connexion s'est terminée. |
| E-NET-002 | NET | La connexion WebSocket s'est fermée avec un code anormal (autre que 1000, 1001 ou 1005) : 1006 coupure sans fermeture propre, 1008 violation de politique, 1009 message trop gros, 1011 erreur du serveur (SPEC-BANC-099). | Le code, la raison et `propre` (fermeture négociée ou non) sont dans les données ; chercher la même heure dans le journal du serveur (`logs/serveur-<date>.log`). |
